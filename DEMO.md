# btech — full demo (HTSS treasury + stealth receiving)

A self-custody Bitcoin treasury where **no one ever holds the key** (DKG + grouped
HTSS threshold signing), coordinated over **Nostr channels**, that also receives
**silent payments** on Bitcoin L1 *and* Arkade from one published address.

~2 minutes, five beats. Every signature is a real grouped HTSS round in Rust
(dkgkit), verified BIP340.

---

## Setup (before the clock)

```bash
# 1. Nostr relay (coordination):
docker compose -f ../dkgkit/examples/self-hosted-relay/docker-compose.yml up -d   # ws://127.0.0.1:7777
# 2. HTSS vault backend (DKG once, then fast signing) — this seeds the demo personas:
cd ~/project/btech && cargo build && ./target/debug/vaultd                          # http://127.0.0.1:8787
# 3. arkd regtest stack up (for the stealth beat). Console:
PORT=3030 bun run dev                                                                # :3030
open http://localhost:3030      # the "Savara" console — tap a demo persona (Alice·Founder, …) or paste an nsec
# 4. keep a second terminal in the SDK repo for the stealth beat:
cd ~/project/hackathon/arkade-ts-sdk
```

> The one-tap **demo personas** appear once `vaultd` is up (they're derived from the
> vault invites). Without it you can still log in via NIP-07 or a pasted `nsec`.

## 1 · The vault — threshold custody, no single key (0:00–0:30)

Open a channel → **TREASURY VAULT** (a *Live DKGKit vault*).

- Point at **VAULT POLICY**: `(1,2,3)-of-(2,3,5)` across **C-level / Managers /
  Operators**.
  > "The spending key was generated by **DKG** — it never exists in one place. A
  > spend needs a quorum from **each** tier; a high-rank signer can't substitute
  > for a missing lower one. That's **HTSS** — hierarchical threshold signing."
- Show the **Receive address** (one Taproot address) and **On-chain balance ·
  regtest** / **TOTAL ACROSS VAULTS**.

## 2 · Propose + threshold-sign a spend (0:30–1:05)

- **Propose a BTC transfer** (Send) → it appears as **PROPOSED · AWAITING YOUR
  SIGNATURE**.
- Use **SWITCH SIGNER · DEMO** to move between signer personas; each clicks
  **Approve & sign**.
  > "Each approval runs a real grouped-HTSS signing round in Rust. When the quorum
  > is met across the tiers, the partial signatures aggregate into a **single
  > BIP340 Schnorr signature** — verified on-chain-style — then broadcast."
- The signer set, group key, and digest are shown; the spend broadcasts to regtest.

## 3 · Governance — reshare without changing the address (1:05–1:25)

- **PROPOSE A POLICY CHANGE → + Propose new signer**.
  > "Rotate the signer set or refresh shares — onboard/offboard a signer, recover a
  > lost device — **without changing the vault address or exposing the key**. The
  > change is itself proposed and approved (governed reshare)."

## 4 · Channels + audit (1:25–1:40)

- **CHANNELS** sidebar (`#treasury-ops`, `#cold-reserve`, `#ops-petty-cash`) + a
  **DIRECT** message with Bob. Each channel is a members-only room mapped to a vault.
- Open **#treasury-ops**: the header carries the channel's **LIVE** on-chain
  receive address **and** its **STEALTH `tsp1…`** address side by side. Type `/send`
  (or tap ₿) to propose a transfer — "Signed with your Nostr key and relayed over
  Nostr." **🔒** messages are **NIP-44 encrypted**.
- **Audit log** (right rail, *"Visible to vault members only"*): every propose /
  sign / message, e.g. `Alice signed ✓ SUCCESS · signed 1/7`,
  `quorum reached 6/6 — live HTSS aggregate verified`, `Broadcast 6.0 BTC … tx 141b7d20…`.

## 5 · Stealth receiving — silent payments, L1 + Arkade (1:40–2:00)

Open **http://localhost:3030/stealth**. Point at the static **`tsp1…`** address.
> "One **BIP-352** address, validated against the official test vectors. It receives
> on Bitcoin **L1** and **Arkade** alike, detected with a **view key** only — never
> learning the one-time key in advance, unlinkable to third parties."

Run, refreshing the page after each:

```bash
BTECH_URL=http://localhost:3030 bun run examples/node/silent-payment-send.ts   # Arkade off-chain → +10,000
BTECH_URL=http://localhost:3030 bun run examples/node/silent-payment-l1.ts     # Bitcoin L1 on-chain → +99,000
```

> "Two rails, one address. And the **same HTSS quorum** spends a detected stealth
> coin via the silent-payment tweak (`silent_payment_leaf_tweak`) — so receiving
> privately and spending by committee are the same vault."

*(No-infra fallback for beat 5: click **Simulate inbound payment** 2–3×.)*

## What it proves

| Beat | Feature | The claim |
|---|---|---|
| 1 | DKG + HTSS vault | no single key; org-shaped quorum |
| 2 | Propose → Approve & sign | real grouped HTSS, BIP340-verified, broadcast |
| 3 | Reshare | rotate signers, same address |
| 4 | Channels + audit | Nostr-coordinated, member-only, NIP-44 |
| 5 | Stealth receiving | one BIP-352 address, L1 + Arkade, view-key detect |

Built on [**DKGKit**](https://github.com/cheng-chun-yuan/dkgkit) (HTSS/TSS in Rust) + **@arkade-os/sdk** (Arkade) + the
`lib/silentpayment` BIP-352 core. See `STEALTH_DEMO.md` for the silent-payment
deep dive.
